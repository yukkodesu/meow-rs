# FlClash-Meow desktop host

Fork-specific embedded host for FlClash-Meow. The standalone `meow` CLI keeps its own startup path. This crate embeds the existing configuration, tunnel, listeners, DNS, provider and API modules in one process; the IPC adapter calls the in-process API router and does not open an internal REST socket or spawn a second core.

The executable accepts one product IPC address. Windows addresses begin with `\\.\pipe\FlClashMeowCore_`; Unix socket basenames begin with `FlClashMeowSocket_`. Frames use four-byte little-endian lengths with a 64 MiB limit. Request and response payloads retain the Dart envelope and encode structured values once. Control responses and state events have separate queues from bounded bulk events. `shutdown` waits for runtime teardown, flushes the response and then closes IPC.

`getCoreInfo` declares protocol version 1 and host/core source identity. `initClash` initializes an absolute product home without opening proxy listeners. `setupConfig` reads the derived `config.yaml`; profile reads return the original YAML mapping. `checkConfig` returns structured diagnostics; `validateConfig` keeps the legacy string result. Unknown fields and ignored capture settings prevent application. A process-local optional validator in `meow-config::proxy_parser` applies the same host policy to provider nodes before materialization, including later refreshes. The CLI does not install it.

Both validation methods require initialized product-home authorization before rebuilding a profile. Applied, staged and retired runtimes remain session-owned until cleanup succeeds. An unconfirmed release appears in `getRuntimeState.failure`, blocks new startup/configuration/provider mutations and leaves IPC available for another shutdown attempt. Successful shutdown closes IPC only after its correlated acknowledgement is flushed. External cancellation remains effective when a peer stops reading responses.

When `authentication` is configured, structured validation reports a warning that the existing core always exempts sources `127.0.0.1/32` and `::1/128`. An empty `skip-auth-prefixes` does not remove these fixed defaults; configured prefixes add exemptions. HTTP and SOCKS authentication apply to other source addresses. The host does not change these core semantics.

TUN readiness retains the core's 300-second allowance for first-time driver setup. A later stop or shutdown cancels only startup work, then waits for retained listener tasks, DNS tasks, native leases and core completion. Cancellation never treats an interrupted cleanup future or process exit as release confirmation.

`getRuntimeState` additionally reports `listeners: [{name,type,address}]`, `dnsListen` and `externalController` from successful socket binds. Idle state reports empty/null addresses. Traffic rates use byte deltas divided by the elapsed sampling window; repeated readers share that sample without consuming the REST sampler. Startup and periodic geodata work use the existing public `meow_app::geodata_fetch` functions and belong to the runtime task set. Geodata and dashboard paths resolve inside the product home, including default resource filenames; provider traversal and symlink escapes are rejected before materialization. Named direct aliases receive a blocking diagnostic because the existing adapter always exposes `DIRECT`.

`cargo test -p flclash-meow-host --tests` exercises framing and the public request boundary. Windows native builds require MSVC, CMake, NASM and libclang, and a signed architecture-matching Wintun DLL. `MEOW_WINTUN_DLL` may point at the verified official DLL; it is embedded by `meow-listener`. `MEOW_HOST_COMMIT` identifies an archived build input when Git metadata is absent.

## Integration acceptance still open

The current Windows tests prove idle initialization, malformed YAML and unknown nested option diagnostics, unknown provider-node rejection, real HTTP proxy transmission, eager listener readiness, stop and restoration after an occupied-port replacement. File-provider members are visible, selectable and delay-probed through the public RPC boundary; a failed refresh preserves valid members. Framed session tests verify a correlated shutdown acknowledgement is flushed before EOF. They do not certify native TUN, system DNS/routes, elevation or the other desktop architectures.

Native ownership uses a durable, private journal written before each DNS or route change. Cleanup restores only values still equal to this generation's installed value; later changes from another writer are preserved. Windows DNS uses adapter GUID and address family and does not reset unrelated adapters. Linux resolver restoration additionally compares the file's device/inode. Routes record the exact device and route fingerprint. Partial setup rolls back the installed subset and leaves failed restoration entries for recovery.

`Tunnel::stop_tun`, `set_tun_handle` and `teardown_tun_handle` return cleanup results. Native guards report restoration failures, and lwIP exit timeouts stay sticky. Runtime retains a pending TUN task before awaiting readiness; stop awaits task, native leases and lwIP teardown. `resources_release_unconfirmed` blocks successor generations. The IPC session owns its cancellation, writer, log and request tasks. Request concurrency is bounded to 64 requests and 64 MiB of pending encoded payloads. Trusted native subprocesses have a 20-second deadline and a 1 MiB output bound, and timeout children are killed and reaped.

Product recovery lives separately from user caches: `/var/lib/flclash-meow/tun`, `/Library/Application Support/FlClash-Meow/tun`, or the Windows CommonApplicationData `FlClash-Meow/tun` directory. Directories/journals permit only root or Administrator/SYSTEM writes; journal content remains private while read-only filename metadata permits a clean ordinary startup; an OS file lock excludes simultaneous setup/recovery, and recovery rejects live owners and invalid journals. `getRuntimeState.recovery` distinguishes `clean`, `recovered`, `needsPrivilege` and `failed`. An unprivileged process that cannot inspect previous TUN state reports that uncertainty and permits ordinary proxy initialization; TUN startup requires confirmed native recovery. Forced termination can leave journaled residue, so a process exit alone is not native restoration evidence.

Unix initialization uses the connected socket's authenticated UID/GID to authorize the existing product home. Cache access stays behind a directory capability and uses caller ownership; no process-global credential changes or recursive ownership rewrites are used. The standalone CLI remains independently buildable and does not install the host's product-home policy or FlClash recovery path. The legacy Linux unowned `.meow-backup` restoration is removed; automatic crash recovery is available to listeners supplied an explicit protected recovery directory. Existing legacy sidecars require manual inspection rather than an unsafe blind overwrite.

Windows initialization captures the connected named-pipe server's process token and retains its process handle. Product-home access uses that caller's authority on individual synchronous filesystem operations, including when the host runs elevated. Managed directory and file handles reject reparse points, hard links and escapes; immutable authorization covers profile/config reads and provider/resource/cache writes. Elevated hosts reject caller-supplied `external-ui` directories because static serving does not use these managed handles. The built-in dashboard remains available. Native recovery journals use their separate privileged policy.
No capability-parity extensions are planned. These are required host ownership and cleanup fixes, with real platform records required by the client specification.

## Verification record

The Windows caller-authority regression runs the production executable against an actual named-pipe server. Before the fix, a profile hard link exposed a fixture file outside the product home. After token-bound authorization, the same RPC returns `config_read_failed`; an ordinary profile, configuration, local HTTP proxy traffic and acknowledged process shutdown still pass. The local Windows x64 host suite now has 13 passing ordinary cases, with the privileged native acceptance harness still ignored. Elevated-to-ordinary-user and handle replacement evidence belongs to the managed-storage platform fixtures.

Windows x64, 2026-10-06, Rust 1.98.1/MSVC: `cargo fmt --all --check`, `cargo test -p flclash-meow-host --tests` (12 ordinary tests), `cargo clippy -p flclash-meow-host --all-targets --no-deps -- -D warnings` and `cargo build -p flclash-meow-host` passed. Public RPC/session regressions cover failed cleanup retaining the session, visible native failure, startup superseded by a later stop while core release is pending, validation requiring initialization, and shutdown under response backpressure. The Unix peer fixture additionally verifies authenticated-home rejection, preserved profile reads and a real bound listener; it is compiled out on Windows and requires a Unix run. The native lwIP build emits its existing Windows build-script/linker informational warnings. Initial native builds failed without libclang, NASM, and an available Wintun input; isolated libclang 18.1.1, NASM 3.02 and official architecture-matching Wintun 0.14.1 resolved those prerequisites. No native TUN, Unix or arm64 acceptance is claimed by this record.

The ordinary H2 fixture adds real ephemeral DNS/API/proxy endpoints, a DNS hosts reply, product-home dashboard serving, tracing filter changes and RFC3339 logs, mode/log atomic validation, elapsed traffic rates and total reset, geodata socket cancellation/restart, and cancellation of a pending HTTP provider preparation. It runs on the default Windows test stack. Heap-pinning the existing core build future at the host boundary resolved a debug-stack overflow for DNS configuration; the production executable also passed the client's DNS-enabled CoreController E2E with its normal stack. CI fixtures must use local resource files or loopback URLs rather than contacting public geodata servers.

Native contract fixtures exercise public `OwnedResources` with local journal files and an OS-boundary resource fixture: partial setup/restoration failures, durable retry, crash recovery, live-owner refusal, route conflicts and preservation of later DNS writes. Public Tunnel tests verify failed lwIP termination cannot permit a successor. An actual child-process fixture verifies the native command deadline, output cap and reaping. Canceled stop fixtures also verify the retained generation completion signal. These tests never change the workstation's DNS/routes. Strict Clippy for `meow-tunnel`, `meow-listener` and `meow-api` passed on Windows x64 after these changes.

The final local slice passed 11 Windows host/IPC/runtime cases, six native ownership/command fixtures, two public Tunnel cleanup contracts, six existing Tunnel lifecycle cases, 114 listener unit cases, the API cleanup error case and nine standalone CLI TUN startup cases. `cargo check -p meow-app --bin meow` used the CLI's full default features. The Unix peer-home fixture is compiled only on Unix and has not run on this Windows workstation.

`tests/native_desktop.rs` is an ignored executable acceptance harness for a disposable privileged runner. It uses the production framed IPC transport, real Fake-IP TUN TCP/UDP and DNS traffic to local origins, native DNS/route snapshots and installed ownership journals. It covers stop/restart, acknowledged shutdown, IPC EOF, Unix SIGTERM and forced process termination followed by initialization recovery. Its finalizer reaps the owned process and invokes only the product's verified native recovery. Snapshot restoration failures fail the test and preserve evidence in JSON test output. Run the test executable with `MEOW_DISPOSABLE_NATIVE_RUNNER=1` and `--ignored --nocapture`; ordinary test runs do not execute it.
